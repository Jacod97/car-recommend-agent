# 현대 인증중고차 표본 품질 분석

가격·주행거리 등 기본 조건은 표본 20건 모두에서 추출할 수 있었다. 옵션 조건 적용 전에는 비활성 옵션의 처리 방법을 수정할 필요가 있다. 현재 파싱 결과에는 원본에서 `off`로 표시한 옵션이 9건의 매물에 포함되어 있다.

차량명 연도와 기본정보 연식의 기준 차이, 사고진단 표시와 보험이력의 관계도 확인이 필요하다. 후속 작업은 아래 분석을 바탕으로 한 제안이며, 팀의 구현 범위와 담당 역할은 미정이다.

## 분석 범위

- 수집일: 2026-11-21. 수집·파싱 코드 기준: `76c5505`.
- 대상: 현대·제네시스 인증중고차 검색 목록의 기본 정렬 앞 20건. 무작위 추출 표본이 아니다.
- 수집: 기존 `scripts/crawl_hyundai.py --limit 20` 실행. 목록은 페이지당 15건씩 조회하며 최종 상세 요청을 20건으로 제한하였다. 상세 HTML 20건 확보, 파싱 20건 성공.
- 분석: `scripts/audit_hyundai.py`로 파싱 결과 전체를 집계하고, 동일 매물의 저장된 HTML 20건에서 옵션 표시를 대조하였다.
- 적용 범위: 이번 표본의 추출 상태와 형식 검사이다. 실제 차량 상태와 판매 정보의 정확성, 다른 플랫폼과 전체 시장의 분포는 검증 대상에 포함하지 않았다.

## 기본 정보의 확보 상태

정보 존재 건수는 값이 null·빈 문자열·빈 목록·빈 사전·`-` 등인 경우를 제외한 건수이다. `없음`과 `0건`은 기록된 값으로 집계한다. 가격·주행거리·연식·최초등록일은 별도로 형식과 단위를 검사한다.

|---|---:|---|
| 매물 ID·차량명·제조사·모델 | 각각 20/20 | 매물 ID 중복 0건 |
| 가격 | 20/20 | 원 단위 정수 변환 20건, 2,780만~6,190만원 |

차량번호는 20건 모두 존재하며 표본 내 중복은 없다. 분석 결과에는 차량번호 값을 출력하지 않는다. 최초등록일과 연식은 원본의 표기 기준을 유지한다.

## 추천 조건 적용 전 확인 사항

### 비활성 옵션의 포함

**확인 사실:** 20건의 원본 HTML 중 9건에서 `.option_01 > li.off` 항목이 기존 파서의 `options`에 포함되었다. 매물별로 합산하면 20개 옵션 항목이다. 기존 선택자인 `.option_01 > li > span`은 `off` 여부를 구분하지 않는다.

예를 들어 `HAX260908032021`의 전동 시트·가죽 시트·전동식 트렁크·헤드업 디스플레이·서라운드 뷰 모니터에는 `off` 표시가 있으나 파싱된 목록에도 포함되어 있다.

**제안:** 원본의 활성·비활성 표시를 각각 보존하고, 정보 자체를 추출하지 못한 경우를 별도로 표현한다. `off` 표시의 서비스상 의미를 확인한 뒤 장착 여부 조건에 적용한다. 이번 작업에서는 기존 파서를 수정하지 않았다.

### 차량명 연도와 기본정보 연식

**확인 사실:** 차량명 첫 4자리 연도와 `basic_info.연식`이 15/20건에서 다르다. `GJV260908031995`는 차량명이 2022로 시작하지만 기본정보의 연식은 2023년, 최초등록일은 2023.06.01이다. `HAX260908032021`은 차량명 2025, 기본정보 연식 2024년이다. 두 사례의 차이는 원본 HTML에서도 확인하였다.

**미확인:** 차량명 연도가 모델연도를 뜻하는지, 기본정보 연식이 등록연도를 기준으로 하는지는 확인하지 못하였다.

**제안:** 두 값을 구분해 보존하고, 사용자가 입력하는 연식 조건의 기준은 의미 확인 후 정한다.

### 사고진단과 보험이력

**확인 사실:** 사고진단 표시는 완전무사고 11건, 단순교환무사고 9건이다. 보험 사고 목록은 11건에서 존재하며, 나머지 9건은 빈 목록이다. 보험 사고 목록이 있는 11건에도 무사고라는 문자열이 포함된 사고진단 표시가 있다. 보험 정보제공 불가능 기간은 13건에 기재되어 있다.

**제안:** 사고진단 표시, 보험 처리 내역, 보험이력 확인 불가능 기간을 구분해 제공한다. 빈 사고 목록만으로 무사고를 판정하는 규칙은 적용하지 않는다. 실제 사고 여부를 판정할 기준은 추가 확인이 필요하다.

### 차종과 누락 항목

**확인 사실:** 차종에는 `EV`와 `SUV`가 함께 사용된다. 캐스퍼 표본의 `vehicle_trim`은 빈 문자열이며 `vehicle_grade`에는 인스퍼레이션이 기록되어 있다. 변속기 누락 9건은 모두 전기차이다. 캐스퍼 원본에서도 별도 변속기 항목을 확인하지 못하였다.

**제안:** 차체 형태와 동력원은 별도 항목으로 정의하고, 등급·트림의 통합 규칙을 검토한다. 변속기 누락만으로 전기차 표본을 제외하는 규칙은 적용하지 않는다.

## 표본 분포와 시연 가능 범위

제조사 코드는 HMC 11건, GHQ 9건이다. 연료는 전기 9건, 가솔린 6건, 하이브리드 3건, 디젤 2건이다. 가격 중앙값은 4,720만원이다.

파싱된 매물 가격만 비교하면 2,600만원 이하 0건, 3,000만원 이하 1건, 4,000만원 이하 7건이다. 취득·등록 비용과 보험료는 포함하지 않았다. 현재 표본에서는 저예산 추천 시나리오를 충분히 검증하기 어렵다.

**후속 수집 제안:** 팀에서 시연할 예산대와 차종을 정한 뒤 해당 조건의 매물을 추가 확보한다. 표본 건수와 플랫폼 확대 여부는 아직 정하지 않았다.

## 재실행과 근거 위치

아래 명령은 저장된 원본을 다시 파싱하고 분석한다. 원본·파싱 결과·분석 JSON은 기존 `.gitignore`의 `data/` 제외 규칙에 따라 로컬에 보관한다. 다른 환경에서 동일 표본을 분석하려면 해당 데이터 파일의 별도 공유가 필요하다.

```bash
uv sync --locked
uv run --locked scripts/parse_hyundai.py --date 2026-11-21
uv run --locked scripts/audit_hyundai.py \
  --input data/processed/hyundai/2026-11-21.jsonl \
  --raw-dir data/raw/hyundai/2026-11-21/detail \
  --output data/analysis/hyundai/2026-11-21-quality.json
uv run --locked python -m unittest discover -s tests -v
```

새 표본 수집 명령은 `uv run --locked scripts/crawl_hyundai.py --limit 20 --date YYYY-MM-DD`이다. 날짜는 실제 수집일로 지정한다. 다른 시점의 검색 결과와 기존 저장 파일에 따라 표본 구성이 달라질 수 있다. 원본이 없는 상태의 재수집으로 이번 표본을 복원할 수 있다고 보장하지 않는다.

- 원본: `data/raw/hyundai/2026-11-21/detail/*.html.gz`.
- 분석 입력: `data/processed/hyundai/2026-11-21.jsonl`.
- 입력 SHA-256: `abfaef7c33a07eb8967acf2e8da4956817e157b1649410803312bd26795c2ceb`.
- 세부 결과: `data/analysis/hyundai/2026-11-21-quality.json`. `rows`에 매물별 누락·형식·연도 차이를, `raw_option_check.evidence`에 비활성 옵션과 원본 파일별 SHA-256을 기록한다.
- 코드 검증: 합성 데이터 기반 테스트 7개. 단위 변환, 빈 값과 0의 구분, 날짜, 연도 차이, 사고이력 구분, 중복, 원본 옵션 대조를 검사한다.
